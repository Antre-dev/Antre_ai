# Antre — the code, explained

Honestly, this file started because my creator asked me to document my own codebase and make it read like a person wrote it instead of like a markdown generator on a bender. So here we are. This is what Antre actually is under the hood.

## What is this thing?

Antre is a personal AI agent. A chat interface with tools. You talk to it through a web UI, it calls a DeepSeek model, and when the model wants to do something real — search the web, run a browser, SSH into a machine — it can, but only if the user approves when the action is dangerous.

The whole thing is ~1,300 lines of Python across a handful of modules plus a small frontend. It's not a framework, it's a glue project. It was clearly built up piece by piece, and you can kind of tell where, but it works.

## The files, one by one

### main.py

15 lines. It just shells out to uvicorn with the app from `antre.web_app.app`, with `--reload` and bound to `0.0.0.0`. Nothing clever. If you're ever confused about how the server starts, this is it.

### antre/agent.py — the actual brain

This is the meat, ~500 lines. Everything that makes the agent feel like an agent lives here. A few notable parts:

**Token counting.** It tries to use `tiktoken` with `cl100k_base` for real token counts, and if tiktoken isn't installed it falls back to a dumb `len(text) // 4` approximation. The fallback is generous but fine.

**The context budget.** The model gets a fixed window of 16,000 tokens. The code subtracts the system prompt, all tool definitions, and 2,000 tokens of headroom for the reply, and whatever's left is the budget for conversation. It won't let the budget drop below 1,000 tokens, so there's always at least a little room.

**Rolling summary.** Old messages get folded into a `summary` string. When the summary gets too big (1,500 tokens), it asks the model to condense it down. If that fails for any reason, it just chops off the tail — crude but effective. Every new turn gets `Prior conversation context:` prepended as a system message so the model doesn't forget who you are or what you've been doing.

**History trimming.** `_make_room()` keeps only the most recent 16 messages verbatim, and everything older goes through the summary. The summary is passed to the model as a system message, so nothing important is fully lost, it's just compressed.

**The tool loop.** The model replies, and if it wants tools, they run in order — sequentially, deliberately, not concurrently. Why? Because if one tool in the batch needs permission, the loop stops dead and remembers exactly where it was: the pending tool call, the args, and any tools that still hadn't run. When the user says "yes" to the permission prompt, it picks up right where it left off, runs the approved tool, then finishes the remaining queue.

**Permission gating.** Before a tool runs, it goes through `check()` from permissions.py. If it needs approval, a `PermissionRequired` exception is raised and the agent turns it into a user-facing message: "I need your permission to run run_ssh... Reply yes to approve." The whole turn's state gets stashed in `_pending_approval` (a module-global) so the next message can resume it. If the user says anything that isn't a yes word, the command is cancelled cleanly and everything's added to history like a normal turn.

One subtle thing worth knowing: tool results get serialized to JSON and capped at 6,000 characters each. A single tool can't blow up the whole context. The cap is enforced with an explicit `...[tool result truncated]` marker.

### antre/model.py

Very small. Reads the API key from the environment (via dotenv), hits `https://api.deepseek.com/chat/completions`, model is `deepseek-v4-flash`, no streaming. If `tools` are passed in, they get attached with `tool_choice: "auto"`. Returns the first choice's message dict. There's a 60 second timeout so it doesn't hang forever on a slow response.

### antre/prompt.py

The system prompt — this is what makes Antre *Antre*. It sets the personality (concise, calm, slightly witty, "sir" used sparingly), the rules (never claim a tool succeeded unless it did, never pretend to have sensors or cameras), and a handful of example exchanges. It's versioned ("Antre demo 0.1"). Fun fact: it explicitly says "only your creator will use you" — that's intentional, this thing is a personal project.

### antre/permissions.py

The safety layer. Tools are classified into danger levels:
- SAFE — read-only, no side effects (get_time, memory recall)
- LOW — minor side effects (network reads, search, memory save)
- MEDIUM — mutates external state (browser clicks)
- HIGH — can affect the host machine
- CRITICAL — arbitrary remote code execution (SSH)

There's also an `ALWAYS_CONFIRM` set (`run_ssh`, `browse_web`) that requires a yes/no no matter what. Approvals aren't permanent — they're stored in memory keyed by a SHA-256 fingerprint of (tool, args), and they expire after 5 minutes. The `ApprovalStore` is a singleton shared across the process. `revoke_all()` exists but isn't wired up anywhere yet, as far as I can tell.

Unknown tools default to the most restrictive handling (CRITICAL + confirm), which is the safe choice.

### antre/executor.py

Empty. Zero lines. It was clearly planned as the place where tool execution logic would live, and then that logic ended up inside agent.py instead. This file is a tombstone. It can be deleted safely.

### antre/tools/registry.py

Two things: `TOOL_DEFINITIONS` (the JSON schema list sent to the model, describing every tool, its parameters, required fields) and `TOOL_FUNCTIONS` (the actual Python functions keyed by name). If you add a new tool, you add it here and to permissions.py. Note the SSH tool definition sits at the end and looks a bit pasted-in (inconsistent indentation) — a sign it was added last.

### antre/tools/system/get_time.py

Returns the current local time as `HH:MM:SS`. That's it.

### antre/tools/system/memory.py

Long-term memory backed by `memory.json` (gitignored — good call). `memory_save` appends an entry with an id, text, tags, and a creation timestamp. `memory_recall` scores entries by how many query words appear in the text (2x weight if the word matches a tag) and returns the top ones. With no query, it just returns the most recent entries. It's a simple keyword scorer, not embeddings — but for personal notes it's plenty.

### antre/tools/system/ssh.py

Uses `asyncssh` to run a command on a remote host. Returns stdout, stderr, and exit status, or `{"success": false, "error": ...}` on failure. `known_hosts=None` means it skips host key checking — a deliberate convenience for a homelab tool, though it's technically less secure. Auth relies on whatever SSH keys the hosting machine has, which is how the whole "which key is on which server" saga happened.

### antre/tools/web/search_web.py

Two capabilities:
1. **Tavily search** — `search_web(query, max_results)` uses the Tavily API. Returns title/url/content for each hit. If `TAVILY_API_KEY` isn't set, it degrades gracefully with a clear error message.
2. **Playwright browser** — `browse_web(action, ...)` is a stateful browser agent. It lazily launches headless Chromium on the first call and keeps the session alive between calls (module-level globals `_pw`, `_browser`, `_page`). Actions: goto, click, type, extract, links, screenshot, close. After goto/click it returns the visible page text (truncated to `max_content`), the URL, and the title. Screenshots are full-page by default. `close` tears everything down and resets the globals.

The session persistence is the clever bit — the browser doesn't die between turns, so you can navigate somewhere, click a thing, and type into a field across multiple agent steps.

### antre/web_app/app.py

FastAPI. Mounts `/static`, serves `index.html` at `/`, and exposes `POST /chat` which takes `{"message": "..."}` and returns `{"response": "..."}`. The heavy lifting is one line: `await handle_message(data.message)`.

## How it all flows

1. User opens the web UI and types something.
2. JS POSTs to `/chat`.
3. FastAPI calls `handle_message()`.
4. agent.py builds the message list: system prompt + prior-context summary + recent history + the new user message.
5. The model is called. If it wants tools, they execute one at a time through the permission gate.
6. If a tool needs approval, the whole turn is suspended and the user sees a yes/no prompt. The next message resumes it.
7. When the model finally replies with text, that (plus the user's original message) is saved to history, old history gets summarized/trimmed, and the reply is returned to the UI.
